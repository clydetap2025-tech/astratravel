# AstraTravel

Путеводитель по Казахстану: 17 городов и 90 мест — от Байтерека и мавзолея Ясави до Бозжыры и Баянаула. В Алматы есть подборка тематических кафе для гостей из 13 стран (из Японии — Ramen 77, из Индии — Tandoor и так далее). Интерфейс на русском, казахском, английском и японском.

Всё, кроме ИИ, работает без входа: каталог по городам, свой маршрут, отметки «был(а) здесь», билеты между 17 аэропортами, избранное, готовый план по дням и живая карта Алматы. Заметки ИИ к маршруту доступны после входа.

## Запуск

Нужен Node.js 22.13 или новее.

```sh
npm ci
npm start            # собирает клиент и стили, сервер на http://localhost:3000 (PORT меняет порт)
npm run typecheck    # проверка типов
npm run build        # Worker для Sites (dist/server)
npm run build:demo   # самодостаточный public/index.html, открывается с диска
```

Сервер хранит хеши паролей и сессии в SQLite в `.data/`.

## Экраны и взаимодействие

- **Первый вход** (`#welcome`): глобус со всеми городами — город выбирается точкой или списком, миниатюры мест открываются сразу; затем одна короткая форма (гость или местный, откуда, что интересно).
- **Места** (`#places`): лента городов, шапка города на его фотографии (с параллаксом), статистика и прогресс «Посещено N из M», карта Казахстана. Каталог: поиск (клавиша `/` переходит в поиск, `Esc` очищает), сортировка (рекомендуемые, быстрые, дешёвые), категории, группы «в городе / рядом / на день».
- **Карточка места**: «В маршрут», «Был(а) здесь», «Поделиться» (системное меню на телефоне, иначе ссылка копируется), сердце. Ссылка вида `#places/<id>` открывает место сразу.
- **Маршрут** (`#planner`): «Мой маршрут» — свои остановки по порядку, их можно двигать и убирать, итог по времени и цене и кнопка «Маршрут в картах» (Google Maps со всеми остановками). Ниже — готовый план по дням (без входа) и ИИ-заметки (после входа, если на сервере есть `OPENAI_API_KEY`). В Алматы — живая карта с такси.
- **Билеты** (`#tickets`): демо-поиск, популярные направления с минимальной ценой и временем в пути, лента цен на 5 дней.
- **Избранное** (`#saved`): места, рейсы и «где вы уже были»; пустое — предлагает три места выбранного города.

## Оформление

Liquid Glass везде: одна поверхность (полупрозрачное стекло с размытием, бликом сверху и мягкой тенью) для панелей, карточек, кнопок, чипов, полей, тостов и окон. Основная кнопка — «капля» тёмного стекла. Стекло внутри стекла не размывается второй раз. Навбар — `LiquidNavbar` (Nimbus UI «Waterline»), он остаётся как есть.

Параллакс: фон движется медленнее страницы, фото в шапке города и в карточках чуть смещаются внутри рамки, на первом экране текст и глобус расходятся. Меняются только `transform`, обработчик прокрутки один на страницу, при «уменьшении движения» всё стоит на месте.

Анимации только в ответ на действия: капля под выбранным вариантом, карточка «перетекает» в окно, тост, тема раскрывается кругом от нажатия. Цвет акцента и фон зависят от региона выбранного города.

Иконки нарисованы для приложения (`src/shared/ui/Icon.tsx`): линия 1,7 px поверх полупрозрачного «стеклянного» тела; в плитках `GlassIcon` они подкрашены по категории.

Шрифты: Literata для заголовков и Golos Text для интерфейса (оба с казахскими буквами, OFL). Учитываются `prefers-reduced-motion`, `prefers-contrast: more` и `prefers-color-scheme`.

## Фото мест

У каждого места своё фото с Wikimedia Commons под свободной лицензией (CC или общественное достояние). Автор и лицензия показаны под фото в окне места, полный список — в подвале («Авторы фото»). Если свободного фото места нет, берётся фото города (на карточке подпись «Фото города»), у кафе — блюдо этой кухни («Блюдо этой кухни»).

Для администратора:

```sh
node scripts/fetch-photos.mjs              # скачать фото для мест, у которых его ещё нет
node scripts/fetch-photos.mjs medeu sauran # заменить фото этих мест
```

Откуда брать фото, задаётся в `data/photo-sources.js` (статьи Википедии по порядку). Скрипт сохраняет `public/assets/<id>.webp` (960×720) и записывает автора и лицензию в `data/photos.js`. Запросы идут с паузами; если Wikimedia ограничивает частоту, скрипт можно просто запустить ещё раз.

## Как добавить город или место

1. Город — в `cities` в `data/kazakhstan.js` (код аэропорта, координаты, название и регион на четырёх языках), регион для цвета — в `cityRegion` в `src/components/ui/place-cover.tsx`.
2. Место — вызовом `p(...)` в том же файле: категория, зона, время, цена (`null`, если неизвестна), тексты на четырёх языках.
3. Фото — строка в `data/photo-sources.js`, затем `node scripts/fetch-photos.mjs <id>`.
4. `node scripts/supabase-seed.mjs` обновит `supabase/seed.sql`.

## Приложение на телефоне и компьютере

Сайт устанавливается как PWA (`public/manifest.webmanifest`, `public/sw.js`), работает без сети после первого визита. На телефоне навбар плавает внизу, окна выезжают снизу листом.

## Supabase

Схема для городов, мест, аккаунтов, избранного, сохранённых маршрутов и учёта ИИ-запросов лежит в `supabase/migrations/`, данные каталога — в `supabase/seed.sql`.

```sh
supabase init
supabase link --project-ref <ref>
supabase db push
psql "$DATABASE_URL" -f supabase/seed.sql
```

Каталог открыт на чтение всем. Таблицы пользователей закрыты RLS: каждый видит и меняет только свои строки. Само приложение пока использует вход из `server.mjs` (SQLite); подключение Supabase Auth — следующий шаг.

## Данные прототипа

- `data/catalog.js` — места Алматы с подбором по стране выезда; `data/kazakhstan.js` — остальные города. Адреса — ориентирами, цена только там, где известна.
- `data/tickets.js` — демонстрационные рейсы и цены.
- Избранное, свой маршрут, отметки и настройки хранятся в браузере.
- ИИ: при `OPENAI_API_KEY` сервер запрашивает заметки к маршруту через Responses API (по умолчанию `gpt-4.1-mini`, меняется `OPENAI_MODEL`). Без ключа карточка ИИ честно пишет, что он недоступен.
